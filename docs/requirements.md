## 1. 概要と目的

文化祭の模擬店で、注文の受付・会計・お釣り・番号札・受け渡しを一つの画面群で回せるようにするシステムを作る。

- 目的: 誰が担当になっても、説明なしで会計ミスなく回せるようにする。
- 前提: お客さんは口頭で注文するだけ。スマホやアプリは使わない。番号札だけは現実の物を渡す。
- 運営: テック部のみ。対象は **2店舗**。
- 成功の基準:
  - 初めて触る人が1分以内にレジ操作を覚えられる。
  - 閉店後の締めで **理論現金（釣り銭準備金＋売上−返金）と実際の現金の差額が0円**。
  - 札切れで行列が止まらない。
  - 回線が切れても会計が止まらない。

## 2. 利用者と端末

| 役割 | 使う画面 | 端末 |
|---|---|---|
| レジ係 | レジ画面 | 部員のスマホ / PC（**各店舗1台**） |
| 調理・受け渡し係 | 調理・受け渡し画面 | 部員のスマホ / PC（台数自由） |
| お客さん | 呼び出し表示（見るだけ） | 店先のモニター / タブレット（任意） |
| 店舗管理者（部員） | 店舗の管理画面 | 任意 |
| テック部全体 | 全体の売上画面 | 任意 |

- インストール不要。URLを開けばスマホでもPCでも使える（PWAとしてホーム画面に追加も可）。
- 担当が交代しても、その端末を渡すだけで続けられる。

## 3. 店舗の分離

- すべてのデータ（メニュー、注文、番号札、売上、設定）を **店舗ごとに完全に分ける**。
- 店舗ごとにURLを分ける。

| URL | 画面 | 必要な認証 |
|---|---|---|
| `/{店舗ID}/register` | レジ | 店舗の合言葉 |
| `/{店舗ID}/kitchen` | 調理・受け渡し | 店舗の合言葉 |
| `/{店舗ID}/display` | 呼び出し表示 | なし（番号しか出さない） |
| `/{店舗ID}/admin` | 店舗の管理 | 店舗の管理PIN |
| `/admin` | 全体の売上（2店舗合算） | 全体の管理PIN |

- 合言葉・PINは端末に一度入力すれば保存され、以後は入力不要。
- ある店舗の合言葉では、もう一方の店舗のデータを読むことも書くこともできない（サーバー側で判定する）。
- 合言葉やPINが漏れた場合に備え、管理画面から変更できるようにする。

## 4. 画面と機能

### レジ画面
- メニューを大きなボタンで並べる。押すと注文に追加し、数量は＋−で調整する。
- 合計金額を画面上部に大きく表示する。
- 預かり金の入力: 「ちょうど」「1,000」「5,000」「10,000」のクイックボタンと、テンキー。
- お釣りを自動計算して大きく表示する。**預かり金が合計に満たない場合は確定できない**。
- 押し間違いは1タップで取り消し。確定前なら全消去もできる。
- 売り切れの商品は灰色になり押せない。
- 次に渡す番号札（いちばん小さい空き番号）を提案する。別の番号にも変えられる。
- 接続状態を常に表示する（「オンライン」/「オフライン・未送信◯件」）。
- 空き札が少ないときは警告を出し、全部使用中なら一目で分かる表示にする。

### 調理・受け渡し画面
- 注文を受付順に並べ、番号札・内容・個数を表示する。
- 状態は「調理中 → できた → 渡した」の3段階。色と文字の両方で示す。
- 「渡した」を押すときは注文内容を大きく表示し、取り違えを防ぐ。
- 「渡した」を押すとその番号札は空きに戻る。
- 売り切れの切り替えもここからできる（厨房が先に気づくため）。

### 呼び出し表示
- 「できあがり: 3番、7番」のように、受け取れる番号だけを大きく表示する。
- 「できた」から一定時間たっても受け取りに来ない番号は、別枠で表示する。

### 店舗の管理画面
- メニュー（商品名・価格・売り切れ・並び順）の登録と変更。
- 番号札の総数の設定と、札の一覧（空き / 使用中、紐づく注文）。
- 札を手動で「空きに戻す」操作（確認ダイアログ付き）。
- 確定後の注文のキャンセル（理由を入力し、履歴に残す）と、札番号の変更。内容を変える場合は、キャンセルしてからレジで入力し直す（金額の差額計算を間違えないため）。
- 釣り銭準備金の入力と、レジ締め（第7章）。
- CSV書き出し。
- 合言葉・管理PINの変更。

### 全体の売上画面（テック部用）
- 2店舗の売上を並べて表示し、合算も出す（第7章）。

## 5. 会計の流れ

1. お客さんが口頭で注文する。
2. レジ係がメニューのボタンを押して注文を入力する。
3. 合計金額を伝えてお金を受け取る。
4. 預かり金を入力し、表示されたお釣りを渡す。
5. 提案された番号札を渡し、会計を確定する。
6. 注文が調理・受け渡し画面に表示される。
7. できあがったら係が「できた」を押し、呼び出し表示に番号が出る。
8. お客さんが札を見せ、係が商品と引き換えに札を回収して「渡した」を押す。
9. その番号札が空きに戻る。

確定後の訂正は、店舗の管理画面から履歴を残して行う。

## 6. 番号札の管理

- 札の総数は店舗ごとに設定する。**初期値は各店舗30枚**とし、リハーサルや当日の状況で変更する。
  - 目安: 札の枚数 ≒ ピーク時の1分あたりの会計数 × (調理の待ち時間＋受け取りの遅れ)[分] × 1.5
  - 例: 1分に2件 × 10分 × 1.5 = 30枚
- 2店舗で番号が混ざらないよう、**店舗の記号を付ける**（例: A-5、B-5）。画面の表示と現物の札を同じ表記にする。
- 現物の札は、店舗の色で作り、番号を大きく書いてラミネートする。6と9は下線で区別する（6̲、9̲）。
- 札が足りなくなるのは調理が追いついていないサインとして扱う。札を増やしても待ち時間は短くならない。
- **札を割り当てるのは各店舗のレジ1台だけ**。そのため、同じ番号が二重に割り当てられることはない。
- 「渡した」で自動的に空きに戻る。返却忘れや紛失には、手動の「空きに戻す」で対応する。
- 番号札は使い回すため、**注文は札番号とは別の注文番号（店舗内の通し番号）で管理する**。

## 7. 売上の確認とレジ締め

### いつでも見られるもの（店舗の管理画面・全体の売上画面）
- 売上合計、注文件数、客単価。
- 商品別の個数と金額。
- 時間帯別の売上（30分ごと）。
- 理論現金 = 釣り銭準備金 + 売上 − 返金。
- キャンセル・修正の件数と金額。
- 開催日ごとに切り替えて表示する（複数日開催に対応）。

### レジ締め（閉店後）
1. 管理画面で「レジ締め」を開く。
2. 実際に数えた現金を金種ごとに入力する（10,000円 / 5,000円 / 1,000円 / 500円 / 100円 / 50円 / 10円 / 5円 / 1円）。
3. 理論現金との差額を表示する。
4. 締めの結果（日時・入力者メモ・差額）を記録する。
5. CSVを書き出して保管する。

### 計算のルール
- 売上は、キャンセルされていない注文の合計とする。
- 注文明細には、**確定した時点の商品名と単価を保存する**（後から価格を変えても過去の売上は変わらない）。

## 8. 技術構成

| 項目 | 方針 |
|---|---|
| ホスティング | Cloudflare Workers（静的アセット配信＋API） |
| データ保存・同期 | Durable Objects（**1店舗＝1オブジェクト**、内部のSQLiteに保存） |
| リアルタイム同期 | WebSocket（Hibernation API） |
| フロントエンド | Vite + React + TypeScript、PWA |
| サーバー側 | Hono（Workers上） |
| 費用 | Cloudflareの無料枠に収まる見込み（2店舗規模。試作で確認する） |

### この構成を選ぶ理由
- 店舗ごとに1つのDurable Objectを持たせると、**店舗のデータが構造的に分かれる**。札の割り当てや状態の更新も1か所で順番に処理されるため、データが食い違わない。
- ホスティング・API・データベースをCloudflareだけで完結できる。

### デメリット
- Firebaseと違い、オフライン時の同期を自分で実装する必要がある（第9章）。
- Durable Objectsは情報が比較的少なく、学習コストがある。

## 9. オフライン方針

会場は学校の敷地のため、部員のスマホのモバイル回線を主に使う。学校のWi-Fiや持ち込みルーターには頼らない。

1. **アプリはオフラインでも開ける**: PWAとして画面一式を端末に保存する。
2. **レジはオフラインでも会計を続けられる**:
   - 注文は端末側で一意のIDを付けて作り、端末内（IndexedDB）の送信待ちリストに保存する。
   - 番号札は、最後に受け取った札の状態と送信待ちの注文から、端末側で割り当てる。
   - 回線が戻ったら送信待ちを自動で送る。同じ注文を2回送っても二重登録されない（ID単位で重複を無視する）。
3. **厨房がオフラインのとき**: 「渡した」は回線が戻ってから送られる。その間、レジ側では札が使用中のまま見えるが、別の空き番号を提案するので問題は起きない。
4. **画面に接続状態を出す**: 「オフライン・未送信◯件」の間は、厨房に注文が届いていないことが分かるようにする。
5. **紙運用への切り替え**: オフラインが続く場合、レジは注文内容を口頭で厨房に伝える。紙の注文票を各店舗に用意しておく。
6. **運用ルール**: オフライン中は端末を再起動しない・ブラウザのデータを消さない。

## 10. 使いやすさの要件（ユニバーサルデザイン）

初めて触る人、色の見分けが難しい人、スマホに慣れていない人、先生や保護者が手伝う場合も含め、**誰でも説明なしで使える**ことを目標にする。

### 10.1 見やすさ
- **色だけで区別しない**。状態・店舗・警告は、必ず「色＋文字＋形（アイコンや位置）」の組み合わせで示す。
- 色の組み合わせは、色覚の違いがあっても区別しやすいもの（青とオレンジなど）を使い、赤と緑だけの区別は避ける。
- 文字と背景のコントラスト比は4.5:1以上（WCAG 2.2 AA）。屋外の直射日光でも読めるよう、薄い灰色の文字は使わない。
- 文字サイズは本文16px以上、金額（合計・お釣り）はスマホで40px以上。端末の文字サイズ設定を大きくしても崩れないようにする。
- 金額は「1,200円」のように桁区切りと「円」で表示する。

### 10.2 押しやすさ
- ボタンは48×48px以上、ボタン同士の間隔は8px以上。
- 主なボタン（「支払いへ」「会計を確定」）は、画面下部の同じ位置に横幅いっぱいで置く。片手でも、利き手に関係なく押せる。
- 「取消」「全消去」など戻す操作のボタンは、主なボタンから離して置き、見た目も変える。
- 押した瞬間に見た目が変わる。対応する端末では短く振動させる（Androidのみ。iPhoneのブラウザは未対応）。

### 10.3 分かりやすさ
- 1画面で1つのことだけをする（スマホのレジは「注文」と「支払い」の2段階）。
- 文言は短い日本語にする（「確定」「取消」「できた」「渡した」）。アイコンだけのボタンは作らない。
- 押せない理由を表示する（例: 「預かり金が200円たりません」）。
- よく使う操作は確認なしで実行し、1タップで元に戻せるようにする。取り返しのつかない操作（キャンセル・札の強制返却）だけ確認を挟む。

### 10.4 間違いを防ぐ
- 画面のヘッダーを店舗の色にし、店舗名を常に表示する。別の店舗の画面を操作する事故を防ぐ。
- 「渡した」を押すときは、札番号と注文内容を大きく表示して取り違えを防ぐ。
- 預かり金が合計に満たない場合は確定できない。

### 10.5 お客さん向け（呼び出し表示）
- 番号を特大の文字で表示する。耳の聞こえにくい人にも伝わる。
- 番号が出たときに音を鳴らせるようにし、店員は口頭でも呼ぶ。目の見えにくい人にも伝わる。
- 番号に加えて「できあがり / Ready」と併記する。

### 10.6 その他
- 営業中は画面がスリープしないようにする（Wake Lock API）。
- ボタンや見出しは正しいHTML要素で作り、読み上げ機能でも操作できるようにする。

## 12. 模擬店で起きやすい問題と対策

| 起きやすい問題 | システムでの対策 | 当日の運用 |
|---|---|---|
| 会計の直後に入力ミスに気づく | レジの「履歴」から、会計後5分以内なら合言葉だけで取り消せる（理由を選び、履歴に残る）。5分を過ぎたら管理PINが必要 | 取り消したら返金し、札を回収する |
| お釣りを間違える | お釣りの金額に加えて、渡し方（例: 1,000円×4・100円×1）を表示する | 表示どおりに、大きいお金から数えて渡す |
| 用意した数を超えて売ってしまう | 商品ごとに「残り数」を設定できる。売れるたびに減り、0 で自動的に売り切れ。残り10以下でレジに「残りN」と出る。取り消すと戻る | 開店前に用意した数を入れる。途中で追加で作ったら入れ直す |
| 途中で売り切れる | 厨房の「売り切れ」ボタンで、レジにすぐ反映される | 並んでいるお客さんに口頭で伝える |
| セット割・タイムセール | 価格をマイナスにした商品（例: セット割 −100円）として登録し、レジで一緒に押す。価格は管理画面からいつでも変えられる（過去の会計の金額は変わらない） | 割引のルールを店先にも掲示する |
| 待ち時間を聞かれる | レジの上部に「調理中 N件」を表示する（スマホの狭い画面では非表示） | 1件あたりの時間を目安に答える |
| 厨房が新しい注文に気づかない | 厨房で「音あり」にすると、新しい注文が来たときに音と振動で知らせる。10分以上たった注文は赤く表示する | 厨房の端末は音が聞こえる場所に置く |
| 札が返ってこない・なくす | 管理画面の「注文」から、使用中の札を空きに戻せる | 予備の札を数枚用意しておく |
| 電波が切れる | 会計は端末に保存して続けられる。戻ったら自動で送る | 厨房に口頭で伝える。端末を再起動しない |
| レジ締めで現金が合わない | 金種ごとに数えて差額を出す。取り消し・変更はすべて履歴に残る | 差額が出たら、履歴と CSV で原因を探す |
